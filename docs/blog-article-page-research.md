## 2. 記事ページの「型」（共通項を Locore の数値に落としたもの）

冒頭（ヒーロー）— 写真の全画面はやめ、縦組み:
1. パンくず（読みもの › 大学院出願）
2. カテゴリ（得意分野の第 1 階層）＋ 国チップ
3. タイトル（28〜32px、太字、最大 2 行想定）
4. サブタイトル（16px、グレー。「何が分かるか」を 1 文）
5. 著者行: 顔 40px・名前・学校（在学中 / アルムナイ）・在籍確認済み・公開日・読了 N 分
6. アイキャッチ（16:9、角丸 12px、任意。無ければ出さない）
7. リード文（3 行以内。本文と区別して少し大きめ）

本文:
- 幅 660px、本文 16.5px、行間 1.9（日本語）、段落間 1.2em、文字色 neutral-800
- H2: 20px 太字、上 2.4em 下 0.8em、左にライムの短い縦線。H3: 17px 太字
- 箇条書き: 黒点、行間 1.8。番号付き: 手順に使う
- 引用: 左 3px ライム罫線＋薄いグレー地＋斜体なし（日本語は斜体が崩れる）
- 囲み（ポイント／注意）: 角丸 12px、薄いライム地 or 薄いアンバー地、先頭にラベル
- 表: 罫線細め、ヘッダは薄グレー、数字は等幅（費用・スケジュール）
- 画像: 全幅 660px、角丸 12px、下にキャプション（12px グレー）
- リンク: 下線＋黒。外部は末尾に ↗
- 埋め込み（YouTube など）: 発信・メディアと同じ facade

導線（読み終わる前に離脱する人を拾う）:
- 本文の 1/3 付近（最初の H2 の後）に**小さな著者カード**（顔・名前・学校・「この先輩に 30 分で相談」ボタン・最安価格）。区切り線で本文から切る
- 末尾に**大きな著者カード**（顔・名前・学校・在籍確認・得意分野チップ・直近の空き・メニュー 2 本）
- その下に「同じ先輩の記事」3 本 → 「同じテーマの記事」3 本 → 「同じ国のエキスパート」4 人
- PC: 右レールに目次（H2 を追従、現在地をライム）。モバイル: 下部固定バー「◯◯さんに相談する」
- 共有はタイトル下に小さく（X・LinkedIn・コピー）。ハート・保存は残すなら控えめに

書体・色:
- 白基調（cream をやめる）、ゴシック（Noto Sans JP 系）、ライムは「アクセントの線と CTA」だけ。粒子アニメと全画面写真は使わない

## 3. データ・執筆側で必要になること

- articles に `subtitle`（1 文の要約）と `lead`（リード文）、`topic`（得意分野の第 1 階層）を追加（additive・0091 案）
- 本文は見出し・引用・囲み・表・画像キャプションを書けるブロック形式に（執筆画面の整理は次のテーマ）
- 読了時間は本文文字数 ÷ 500（日本語）で自動計算
- 著者情報は /experts/[id] と同じデータ（学校・在籍確認・得意分野・最安メニュー・直近の空き）を流用

## 5. 追記（2026-09-06）: リンクカードと埋め込みの仕掛け

「芋っぽくなる」二大要因は、文中に散らばる下線リンクと、大きさが暴れる埋め込み。どちらも「本文幅 640px の同じ枠」に揃える。モック: `mockups/v2/article-page-editorial.html` の EMBED KIT。

### 5.1 リンクは文中の下線ではなくカードで

| 種類 | 判定 | カードに出すもの | データの出どころ |
| --- | --- | --- | --- |
| Locore の記事 | `/articles/[id]` | キッカー「LOCORE の記事」・タイトル・要約 2 行・著者・テーマ・読了時間・右にカバー | articles |
| エキスパート | `/experts/[id]` | 顔・名前・学校（在学中/アルムナイ）・在籍確認・得意分野 3 つ・最安価格・直近の空き・「この人に相談する」 | /experts/[id] と同じバンドル |
| 外部サイト | それ以外の http(s) | ドメイン・OG タイトル・OG 説明 2 行・右に OG 画像。取れなければ右の面はドメインの頭文字 | 0088 の linkPreview（サーバー側で 1 回取得・キャッシュ） |

文中のインラインリンクも残す（固有名詞に添える程度）。段落として貼られた URL 1 本 = カードに自動変換。

### 5.2 埋め込みの共通ルール（崩れない仕掛け）

1. **枠は 1 種類**: 幅 640px、角丸 12px、罫 1 本、下に「バー」（タイトル・補足・外部リンク ↗）
2. **比率は種類ごとに固定**（aspect-ratio）: 動画 16:9、地図 16:10、単体画像 4:3、2 枚並び 1:1、SNS 投稿は本文の高さに追従するが画像は 16:9 で切る
3. **facade で読む**: 最初はサムネ／静止画だけ（軽い）。クリックで本物（iframe）に差し替える。YouTube は `youtube-nocookie`、地図は Static Maps → Embed
4. **iframe を使わないもの**: X / Instagram / TikTok は oEmbed や OG で取ったテキスト・画像を自前の枠で描く（公式ウィジェットは高さとスタイルが暴れる）
5. **失敗したら同じ枠のまま**「この埋め込みは表示できませんでした」＋ 外部リンクのバー。ページの段組みは変わらない
6. **幅を超えるもの**（列の多い表・コード）は横スクロールの箱に入れる。本文はスクロールしない
7. **画像は object-fit: cover** で枠に合わせ、キャプションは下に 12px グレー。alt は執筆側で必須にしない（任意）
8. **URL を貼るだけ**: 執筆画面に URL を 1 行貼ると種類を自動判定して上の部品に変換（display.ts の detectKind を流用）。手動で「リンクカード」「埋め込み」を選ぶ必要はない

### 5.3 本文データ（ブロック形式）

記事本文はブロックの配列で持つ（Markdown/HTML の生文字列をやめる）:

```
{ type: 'paragraph' | 'heading' | 'list' | 'quote' | 'aside' | 'table' | 'image' | 'images' |
        'link_card' | 'embed', ... }
link_card: { url, kind: 'article' | 'expert' | 'external', preview? }
embed:     { url, provider: 'youtube' | 'gmap' | 'x' | 'instagram' | 'tiktok' | 'spotify' | 'other', preview?, ratio }
```

執筆側は「段落に URL を貼る → 自動でブロック化」、表示側はブロックごとの React コンポーネント（Prose 内で同じ幅）。既存記事の本文（プレーンテキスト）は paragraph に分割して読む。

## 6. 追記（2026-09-07）: スマホの標準サイズと部品の整理

### 6.1 スマホ（〜640px）の文字サイズ — 業界標準に合わせる

| 要素 | PC（640px カラム） | スマホ | 根拠 |
| --- | --- | --- | --- |
| 本文 | 16.5px / 行間 2.0 | **16px / 行間 1.85** | Google 推奨と日本の主要サイトの最頻値が 16px、行間は 1.6〜2.0 で最頻 1.8。Medium・Substack は 16〜18px |
| タイトル（H1） | 40px | **26px** | スマホの記事タイトルは 18〜28px で最頻 24px。H1 24〜32px の範囲の中央 |
| H2 | 24px | **20px** | H2 20〜28px の下限（本文との差を 4px に抑えて詰まりを防ぐ） |
| H3 | 17.5px | **17px** | H3 18〜24px の下限より少し小さく（本文 16px との差 1px＋太字で区別） |
| サブタイトル / リード | 18 / 19px | **15.5 / 17px** | 本文より 1〜2 段階だけ大きく |
| 引用 | 18.5px | 17px | 本文より少しだけ大きく |
| 表 | 14.5px | 13.5px | 14px 未満は 1 段階まで。列が多いものは横スクロール |
| キャプション・脚注 | 11.5〜12.5px | 同じ | 12px 前後が下限 |
| 左右の余白 | — | **20px** | 16〜24px の中央。画像・埋め込みは余白の内側いっぱい |
| 2 列の部品（良い点・気になる点、用語、前後の記事） | 2 列 | **1 列** | 320〜390px 幅では 2 列は読めない |

出典: [Font Size Guidelines for Responsive Websites（Learn UI Design）](https://www.learnui.design/blog/mobile-desktop-website-font-size-guidelines.html)、[Web Font Size Guide: Body, Headings, A11y](https://madegooddesigns.com/web-font-size-guide/)、[What Font Size Should Body Text Be? 16px Minimum](https://www.greadme.com/blog/seo/best-font-sizes-for-readability-complete-guide)、[Typography Matters（Substack）](https://substackcourse.com/typography-matters-choosing-the-right-font-for-your-substack-articles/)、[スマホの文字サイズと行間の最適値](https://omniweb.jp/74-2/)、[【2026年最新】Webデザインのフォントサイズ完全ガイド](https://withcode.tech/media/webdesign-fontsize-optimization-description/)、[フォントサイズ・行間の早見表（TANE-be）](https://tane-be.co.jp/knowledge/web-design/2601/)

実装では px ではなく rem（本文 1rem = 16px）で書き、ブラウザの文字サイズ設定に追従させる。

### 6.2 部品の整理（2026-09-07 の決定）

- **手順（ステップ）は廃止**。順番のある話はタイムラインで書く
- **H2 の番号（01, 02 …）は既定でなし**。付けたい記事だけ執筆側で ON にする（ブロックの属性）
- 残す部品: この記事で分かること / チェックリスト / Q&A / 用語 / タイムライン / 良い点・気になる点 / 数字の見出し / 先輩のひとこと / 脚注・更新日・前後の記事、＋ リンクカード 3 種と埋め込み
